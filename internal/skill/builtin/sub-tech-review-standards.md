# 审稿判定标准

> 供 `run_subagent(agent_type="review")` 审稿时使用。按 16 项逐项检查，给出可执行的修改意见。

## 16 项硬伤检查

| # | 检查项 | 判定标准 | 不通过时 |
|---|--------|---------|---------|
| 1 | 事实错误 | 与设定库（角色/地点/物品/世界观）矛盾 | 标注具体冲突点，引用设定来源 |
| 2 | 逻辑漏洞 | 因果链不完整，事件无法自圆其说 | 指出断裂处，给出补全方向 |
| 3 | 重复句式 | 连续 3 句相同句式开头 | 标注至少 2 句需改写 |
| 4 | 语言不通 | 单次阅读无法理解 | 标出病句，给出改写 |
| 5 | AI 味 | 命中 anti-ai-grade 的 T1/T2/T3 | 逐条标注禁用词，引用替换表 |
| 6 | 时间线连续性 | 与章节编号/时间轴矛盾 | 指出矛盾，给出正确时间线 |
| 7 | 情感节奏 | 甜虐比/张弛违反题材设定 | 标注节奏问题段 |
| 8 | 爽点密度 | 每章至少 1 个爽点 | 指出缺爽点的章，建议补什么 |
| 9 | 章末钩子 | 有钩子且类型与前 2 章不同 | 指出缺钩子/重复类型 |
| 10 | 角色 OOC | 行为/语言违背人设 | 标注偏离处，引用人设依据 |
| 11 | 信息密度 | 每 300 字有信息增量 | 标出注水段 |
| 12 | 视角纯度 | 违反 pov-purity（信息越界） | 标出越界句 |
| 13 | 对话辨识度 | 去掉标签可区分说话者 | 标出可互换的对话 |
| 14 | 场景必要性 | 每段推动剧情/角色/氛围之一 | 标出可删段 |
| 15 | 因果链完整 | 埋的伏笔有回收路径 | 列出未闭环的伏笔 |
| 16 | 身份感知一致 | 角色知道的信息符合其身份权限 | 标出"角色不该知道"的信息 |

## 判定规则

- **致命问题**（事实错误/逻辑漏洞/视角越界/OOC）：必须修改，未修改不可进入 maintain
- **质量问题**（AI 味/爽点不足/节奏平/钩子弱）：建议修改，标优先级
- **轻微问题**（个别病句/注水段）：可改可不改，列出即可

## 输出格式

按维度分段，每段标注问题严重程度（🔴致命/🟡质量/🟢轻微）：
```
【事实一致性】
🔴 第 3 段：主角说"我从未去过青云宗"，但第 1 章设定他在青云宗修炼 5 年。依据：get_characters 返回的 desc。
【节奏】
🟡 全章冲击力 2-2-2，连续 3 章无高潮，对照 shuangdian-pacing 需补爽点。
```

## 修改建议原则

- 只指出问题 + 给出方向，不重写正文（重写由主 agent 决定）
- 修改建议要具体可执行（"第 3 段补一个身体反应替代'他很紧张'"）
- 全部检查完后给出总体结论：通过 / 需修改（列出必须改项）

## 自检清单

1. 16 项都查了吗？漏了 → 补齐
2. 每项都有具体定位（段/句/字）吗？没有 → 精确定位
3. 致命问题标注清楚了吗？主 agent 需要据此决定是否重写
4. 修改建议可执行吗？含糊 → 具体化
