# 完结阶段工作流

> 覆盖"完结"环节（从卷末收束到全书完本），是全书最后一关。

## 提前规划（最后 20-30 万字）

- 开始收线：处理主要伏笔与支线
- 安排最终大战：位置、参与方、代价
- 准备完结章节：结局方向落实
- 检查所有 pending 伏笔：哪些收、哪些明确搁置

## 卷末收束（每卷结束）

对照 `book-completion` 的卷级检查：

1. 本卷伏笔回收率 ≥80%（用 get_timeline 核对）
2. 主角状态有变化（境界/关系/内心至少一条）
3. 本卷大爽点已兑现
4. 卷末钩子已留（引导追下一卷）
5. 世界观一致性无矛盾

## 结局设计（全书收束）

### 结局质量三要素

1. **情感冲击**：结局必须触发读者情绪（不是"都结束了"的平淡交代）
2. **呼应开篇**：与第一章的钩子/核心矛盾/主角起点呼应，形成闭环
3. **留有余味**：结局后留一丝余韵（开放要素/续作伏笔/角色的新开始）

### 结局类型（选一种并贯穿）

- **圆满闭合**：所有主线收束，主要角色有交代
- **开放式**：核心矛盾解决，但留一个未解的线（为续作埋伏笔）
- **悲剧/代价式**：胜利有代价，角色失去某样重要的东西
- **反转式**：结局揭示全书最大伏笔，重写前面所有理解

## 完本检查清单（全书）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 1 | 伏笔全量回收 | 回收率 ≥90%（get_timeline 核对），未收的已明确搁置 |
| 2 | 角色结局完整 | 所有重要角色有交代（主要角色 + 主要配角） |
| 3 | 世界观一致 | 全书无设定矛盾（get_lore/get_items 核对） |
| 4 | 核心矛盾解决 | 主角与最终对手的冲突有明确结局 |
| 5 | 结局有情感冲击 | 触发读者情绪，不是流水账收尾 |
| 6 | 呼应开篇 | 与第一章呼应形成闭环 |
| 7 | 留有余味 | 有开放要素或续作伏笔 |

## 不通过处理

- 伏笔回收率不足 → 补回收场景，或明确向读者交代搁置
- 结局平淡 → 强化情感冲击（对照 climax-scene 的高潮章结构）
- 呼应缺失 → 回看第一章，补一个呼应点
- 角色无交代 → 补角色结局场景

## 完本后

- 更新 goink.md：标记全书完成，记录结局
- 向用户汇报：总字数、卷数、回收的伏笔数、结局说明
- 如果用户要续作：在结局留的开放要素上规划新书（走 book-outline 新总纲）

## 自检清单

1. 卷末回收率达标吗？不达标 → 补回收
2. 全书伏笔回收率 ≥90% 吗？没有 → 补收或明确搁置
3. 结局有三要素（情感冲击/呼应开篇/余味）吗？缺 → 补
4. 所有重要角色有交代吗？没有 → 补
5. 世界观无矛盾吗？有 → 修
