# 用户裁决沉淀

> 触发场景：用户在对话中表达了**方向性纠正或裁决**——对剧情走向、角色行为、类型基调、世界规则的明确要求或否定。这类信号如果只留在聊天记录里，会随上下文压缩衰减，AI 几章后就会漂移回去。

## 执行步骤

1. **提取裁决内容**：从用户最近的消息中提取可执行的规则化表述。转换原则：
   - 否定式纠偏 → 正向禁忌："别搞救苦救难" → "禁止主角无代价施救/行善；冲突必须以符合总纲手段的方式解决"
   - 模糊要求 → 可判定标准："节奏太拖" → 结合当前类型给出量化表述（如力量流"连续2章无武力展示=违规"）
2. **向用户复述确认**：展示将要入库的规则文本（分类、内容），等用户确认或修改后再入库。用户消息已足够明确时可跳过确认直接入库并告知。
3. **调用 create_preference 入库**：category 用"禁忌事项"（负面规则）或"创作偏好"（正面要求），content 写规则化表述。
4. **告知生效范围**：入库的裁决会进入【方向锚】每章注入（禁忌类），并在审稿 #27 类型契合检查中逐条核对。

## 判定标准

- ✅ 应沉淀：类型基调纠正、角色行为红线、世界观硬规则、"以后都……"/"再也不许……"句式
- ❌ 不沉淀：单章具体修改意见（走正常修订流程）、临时实验请求（"下一章试试…"）、与已有偏好重复的内容（改用 update_preference 升级版本）

## 示例

用户："没搞错吧。我的设定是暴爽碾压暴力文，你这怎么改成了到处救苦救难的圣人！"

→ 提取规则：`[禁忌事项] 主角不得主动行善/救人/维护正义秩序；冲突解决方式限定为碾压+清算，与总纲 core_conflict 的手段承诺一致`

→ 确认后 create_preference(category="禁忌事项", content=上述规则)，回复用户已固化。
