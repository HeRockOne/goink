## 3. Goink 对标分析

### Goink 现有能力

| 能力 | Goink | 行业标杆 | 差距 |
|------|-------|---------|------|
| 长篇记忆 | DB结构化存储+get_writing_context树状关联 | 蛙趣拼文BM25+向量+RRF | ⚠️ 缺语义检索（search_story_memory有但精度待验证） |
| 角色管理 | create/update_character+关系图+location关联 | 蛙趣拼文五层模型+时序追踪 | ⚠️ 缺角色别名、缺时间线快照 |
| 伏笔管理 | timeline+reader_perspective+arc_node | 蛙趣拼文8种伏笔+生命周期+强制回收 | ⚠️ 缺超期自动提醒、缺missedCount强制回收 |
| 大纲层级 | outlines/NNN.md+chapter_plan(三层) | 蛙趣拼文三层骨架+卷级+章级 | ✅ 架构支持，缺实现 |
| 世界观设定 | lore模块（arc_id关联） | 蛙趣拼文世界观硬约束注入 | ⚠️ 缺硬约束自动注入机制 |
| 物品追踪 | item+item_occurrence | 蛙趣拼文物品生命周期 | ✅ 基本对齐 |
| 场景管理 | scene+location+location_relation | 蛙趣拼文场景管理 | ✅ 基本对齐 |
| 阶段门禁 | 5阶段+require+edit_paths | 无对标 | ✅ Goink独有优势 |
| 一站式桌面 | Wails桌面+移动端 | 蛙趣拼文VSCode插件 | ✅ 独立桌面体验更好 |
| 消痕/AI味 | 无 | 茄子朱雀引擎/蛙趣22模板 | 🔴 完全缺失 |
| 节奏分析 | stats(字数统计) | 马良节奏曲线+评分 | 🔴 缺紧张度/情绪/冲突量化 |
| 多模型 | LLM配置(支持多provider) | 马良15+模型按Agent配 | ⚠️ 有基础，缺按场景自动切换 |

### Goink 独有优势

1. **阶段门禁系统** — 行业内唯一有 require+next 强制约束的工作流
2. **树状 get_writing_context** — 一次调用获取全部关联数据，替代零散 get_*
3. **HTTP API 23端点** — 外部调试和集成能力
4. **本地数据** — SQLite存储，隐私优先
5. **独立桌面应用** — 不依赖浏览器和云服务

### Goink 核心差距

1. **🔴 AI味消除** — 竞品标配，Goink完全缺失
2. **🔴 节奏量化** — 马良/蛙趣都有，Goink只有字数统计
3. **⚠️ 语义检索精度** — search_story_memory有但缺混合检索（BM25+向量+RRF）
4. **⚠️ 角色别名** — 玄幻角色常有5个名字，Goink只支持name匹配
5. **⚠️ 伏笔超期提醒** — 蛙趣有missedCount≥3强制回收，Goink无
6. **⚠️ 世界观硬约束注入** — 蛙趣在生成时自动注入世界观规则，Goink靠AI自觉

## 4. 行业共识（所有成功长篇AI写作系统的共同点）

1. **结构化记忆 > 上下文窗口** — 所有百万字级工具都用DB/图谱/Lorebook，没有靠窗口硬撑的
2. **写完必须回写** — 天命："不靠上下文，不靠模型记忆，靠状态回写"
3. **阶段门禁/审计** — 蛙趣22模板+27维度、茄子朱雀检测、Goink门禁require
4. **伏笔必须追踪** — 蛙趣8种伏笔+生命周期、Goink timeline+reader_perspective
5. **多模型按场景切换** — 高潮用强模型、日常用经济模型
6. **作者掌控 > AI自动** — 蛙趣："作者管一切，AI辅助管"
