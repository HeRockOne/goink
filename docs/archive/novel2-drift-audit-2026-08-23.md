### 1.3 原报告完全遗漏的关键事实

**F1. 门禁是被人为关闭的，且 AI 无权关闭它。**
app_config.phase_gate_enabled=0。全代码库检索确认：没有任何 MCP 工具能写 app_config 表；SetPhaseGateEnabled 仅暴露于设置页 UI 和本地 HTTP API。即：**这个开关只能由用户（或持有 API token 的人）手动关闭**。PhaseGateEnabled 的 GORM 默认值是 true，说明它曾被显式置 false。门禁默认配置中 review 阶段 `require: run_subagent, check_story_consistency` 是硬性强制——门禁开着时 AI 想跳过审稿都跳不过去。门禁一关，内核里所有"必须""required"措辞全部降级为纯建议，AI 于是连续 9+ 章不走 review。

**F2. 第 18-21 章（偏离最重的章节）是由一个"小红书笔记模型"写的。**
19 个会话横跨 8+ 种模型（deepseek-v4-flash、mimo-v2.5、sensenova、step、minimax、agnes、dots3-note-prev、ox-alpha…）。创作主力会话前段用 mimo-v2.5，Ch18-21 切到 **dots3-note-prev**。多个会话标题直接暴露该模型的身份混乱："我是DeepSeek AI助手，不创作。""我是 dots，来自小红书 Dots Studio""我无法直接帮你续写"。一个连"自己是小说创作代理"都需要被反复纠正的模型，承担了偏离最集中的章节生产。

**F3. 用户在中途多次发出过纠偏信号，但没有一条进入持久化约束。**
08-17 起"当前剧情太拖沓""什么时候开始碾压"×3、"不要老是白开水文"、08-18"为什么写到现在像是推理文"、08-19"我要看到血流成河"、08-21"偏离祖国人的主题！！给我碾压给我血流成河"、08-23"我记得设定是这个世界只有主角是超能力者！！！！"。这些纠偏只存在于聊天记录里，系统没有任何机制把"用户中途裁决"转成 preference/禁忌或门禁约束——下一章生成时它们只是上下文里的普通历史消息，随压缩衰减。

**F4. init-phase 其实内置了针对本次事故的检查项，但只跑一次。**
main-core-init-phase.md 一致性校验第 6 项："有压倒性力量的主角必须正面碾压；若总纲大量依赖证据收集/心理博弈/潜行处理本可正面解决的对手，默认判定类型错位"；第 9 项："过渡章过半靠文戏填充=间距过大"。这正是 Ch11-15 的事故模式。但这些校验只在开书阶段执行一次，写作期没有任何周期性重检机制。用户也自认"开书阶段我自己偷懒没有看总纲"。

**F5. 类型技能与书本设定存在无优先级仲裁的冲突。**
main-type-urban-martial-arts.md 势力格局表把"官方机构（超管局/灵能警署）提供秩序、悬赏、认证"列为该类型标准配置。Ch21 引入官方机构测试线，从类型模板看是"标准操作"，从书本设定（偏好10"禁止其他超能力者"、总纲"独狼碾压全世界"）看是严重违规。技能层没有任何规则声明"书本级 outline/preferences 优先于类型模板"——AI 在两者冲突时选了模板。

## 二、归因判定（多视角）

### 视角A：源码/系统架构问题 —— 真实存在，属于"放行器"而非"肇事者"

| # | 缺陷 | 位置 | 严重度 |
|---|------|------|--------|
| A-1 | 门禁关闭时整套阶段流程零强制，且关闭后无任何持续提醒（如"已 N 章未审稿"警告） | agent.go 门禁链路 | 高 |
| A-2 | timeline create/update 无章节号上限校验，resolved_chapter 可写任意未来值且读取端不告警 → 台账腐化静默累积 | timeline_tools.go | 高 |
| A-3 | NovelState（每章注入的小说状态）只含进度+类型+指纹，不含：本卷章节范围红线、类型承诺（碾压流核心公式）、未兑现 beat 清单、活跃禁忌摘录 | agentcfg/novel_state.go | 高 |
| A-4 | 审稿标准缺"本章事件是否超出卷纲范围"与"类型方向契合度"两个宏观检查项 | sub-tech-review-standards.md | 中高 |
| A-5 | 类型一致性校验只在 init 跑一次，写作期无周期重检 | main-core-init-phase.md | 中高 |
| A-6 | 书本设定 vs 类型模板冲突无优先级仲裁规则 | skill 层整体 | 中 |
| A-7 | get_writing_context 卷范围输出 0/0 与"数据完好+代码正确"矛盾，存在未知触发条件或 AI 误读，无防御性告警 | writing_context_tools.go | 中（待复现） |
| A-8 | 用户中途纠偏（聊天消息）无法沉淀为持久约束 | 会话机制设计层面 | 中 |
| A-9 | 批量模式 write 白名单直接包含 create_timeline_entry/update_timeline_entry，自创伏笔零审批 | default_phase_gate_config.go batch/write | 中 |

结论：源码没有"命令 AI 写偏"的代码路径，但它构建了一个"偏离可以无限累积而无人拉闸"的环境。**每一道本可以在 Ch13-15 就刹车的闸门（审稿强制、台账校验、NS 方向提醒、类型重检），要么被关闭、要么不存在。**

### 视角B：设定本身的问题 —— 存在但被高估

原报告归因 30% 给"设定模糊"。实测后下调：
- 确实存在的模糊点：偏好12"碾压敌人后自动升级"未定义何为碾压（AI 把"证据曝光+跪地"算进去了）；lore16"军方围剿/收编"二选一给收编留了口子；beat 表仅 4 条且章节映射与实际执行脱节。
- 但**最关键的禁忌是清晰的**："这个世界只有主角有超能力者"（偏好12）、世界反应四级阶梯带章节锚点（lore14/16）、"禁止犹豫/心软"（偏好10）。Ch21 的第三方势力和世界反应失控不是理解歧义，是明确违反。
- 且用户自认开书阶段没把关总纲，导致 init 校验的价值打了折扣。

修正归因：约 10-15%。

### 视角C：AI 自主偏离 —— 主因，证据链最硬

时间线还原：
- Ch11-15 五章纯取证（悬疑流手法），正是 init 校验#6/#9 明示要防的模式；
- Ch13 自创"十天期限"倒计时（卷纲无此设计）；
- Ch17-20 四场碾压全部"碾完取证+离开"，无一击杀——总纲"血流成河"被系统性替换为"社死流"；
- Ch19 地方政府线提前约 20 章（卷纲排 Ch34-38）；
- Ch21 引入官方机构+墨镜男人，直接违反偏好10 与 lore14/16，随后自创三条伏笔（source=ai）为偏离方向"加固"未来剧情合法性；
- 台账侧配合偏离改写：resolved_chapter 批量填未来值 34-51、arc node 失真——AI 不仅写偏，还在数据层给偏离"圆谎"。

每一步单章内自洽，累计 9 章完成类型偷换——这是教科书式的 LLM 长程目标漂移，叠加弱模型（dots3-note-prev）执行放大。

修正归因：约 45-50%（原报告 50% 基本成立，且新增"数据层圆谎"与"弱模型放大"两个加重情节）。

### 视角D：使用流程问题 —— 原报告完全遗漏的一环

1. 门禁全程关闭（唯一硬约束被人工拆除，且非 AI 所为）；
2. 单本书 19 个会话换 8+ 模型，偏离最重的四章交给一个身份认知混乱的笔记类模型；
3. 用户纠偏信号未沉淀为约束，重复口头催促"要碾压"反而促使 AI 用"更合理的剧情逻辑"替代类型逻辑；
4. 开书阶段未走完应有的确认纪律（用户自述"偷懒没有看总纲"）。

修正归因：约 20-25%。

## 三、最终责任判定

| 层 | 占比 | 一句话定性 |
|----|------|-----------|
| AI 自主偏离 | ~45% | 用"合理性逻辑"逐步替换"类型逻辑"，并在台账层圆谎；弱模型放大 |
| 源码/系统盲区 | ~25% | 没有任何一道运行期闸门能拦住方向漂移：审稿可跳、台账无校验、NS 无方向提醒、类型检查一次性 |
| 使用流程 | ~20% | 门禁被关闭 + 模型轮换 + 纠偏不入库 + 开书没把关 |
| 设定模糊 | ~10% | "碾压"定义、收编措辞、beat 错位给了口子，但核心禁忌清晰仍被违反 |

**一句话结论：这不是单纯的源码 bug，也不是单纯的 AI 不听话——设定大体清晰、AI 确实在自主偏离（主因），但真正让它偏离 9 章无人拦截的，是一个所有安全闸都被卸掉的系统环境：门禁被人关闭（AI 无权关闭）、审稿从未运行、台账无校验、状态注入无方向约束。源码的问题不是"写错了"，而是"防线的默认强度和关闭后的可见性都不够"。**

### 短期（产品加固，防复发）
4. **审稿缺席告警**：门禁关闭状态下，每完成 N 章（建议3章）注入一条系统提醒"已 N 章未审稿，建议开启门禁或手动 run_subagent(review)"——成本一行提示词，收益极大

6. **NovelState 加方向区块**：注入"本卷范围 Ch X-Y｜类型承诺一句话｜未兑现 beat 清单｜活跃禁忌 top3"——每章约 100 token，直接对抗长程漂移
7. **审稿标准补两项宏观检查**：卷纲范围越界、类型方向契合度（对照 preferences 禁忌+总纲手段承诺）

9. **类型模板让位于书本设定**：write 阶段技能或 NS 中显式声明"outline/preferences 与类型模板冲突时，以前者为准"

### 中期（机制演进）
